Work to deploy ctf-performance

=========================================================================
MENTAL MODEL — two independent layers (don't conflate them)
=========================================================================
Layer 1 — CTFd import (GLOBAL, ONE-TIME)
  Populates the scoreboard: titles, descriptions, points, hints, flags.
  Run ONCE. Every team sees the same challenges and submits the same flags.
  Has NOTHING to do with per-team routing.

Layer 2 — Challenge containers + routing (PER-TEAM)
  docker-compose.challenges.yml launched once per team under a distinct
  COMPOSE_PROJECT_NAME. Caddy routes each team's subdomain to that team's
  stack. This is where "map routing to teams" lives.

Interaction model chosen: WEB-ONLY via Caddy.
  => Teams have NO SSH and NO docker exec. Therefore they need an in-browser
     way to edit code / run SQL. Plan below uses code-server (VS Code in the
     browser), one instance per team, as that in-browser workspace.

=========================================================================

=========================================================================

  also POST hints, using `yq` to parse the hints block:

- Fix path B: adopt ctfcli (official). Requires reshaping each challenge.yml to
  CTFd's schema (value: not points:, flags: not flag:). Keep the custom

- Run: ./scripts/import-challenges.sh https://ctf.performative-performance.com <ADMIN_TOKEN>
  (token from CTFd Admin > Config > Access Tokens)

=========================================================================
PER-TEAM ROUTING (Layer 2) — the main remaining work
=========================================================================
- Add a `code-server` service to docker-compose.challenges.yml:
    * image codercom/code-server, password from env, workspace = mounted
      copy of ./challenges so teams can edit the broken files
    * attach it to the external ctf-edge network so Caddy can reach it
    * it shares the stack's default network, so from its terminal a team can
      reach `challenge-01-db`, `challenge-01-missing-index:8080`, etc. by
      service name over the same Docker network
- Launch one stack per team with an isolated project name + network:
    COMPOSE_PROJECT_NAME=ctf-team1 docker compose -f docker-compose.challenges.yml up -d
    COMPOSE_PROJECT_NAME=ctf-team2 docker compose -f docker-compose.challenges.yml up -d
  Containers become ctf-team1-challenge-01-db-1, etc. Networks are isolated
  per project so teams can't see each other's containers.
- Caddyfile: add one block per team routing subdomain -> that team's code-server:
    team1.performative-performance.com { reverse_proxy ctf-team1-code-server:8080 }
    team2.performative-performance.com { reverse_proxy ctf-team2-code-server:8080 }
  (Consider generating these blocks from a team list rather than hand-editing.)
- DNS: wildcard *.performative-performance.com -> EC2 elastic IP (Cloudflare).
- REWRITE challenge.yml instructions for web/service-name access, since there
  is no docker exec anymore. e.g. challenge 01:
    OLD: docker exec -it ctf-performance-challenge-01-db-1 psql -U challenge -d orders
    NEW: (in the code-server terminal) psql -h challenge-01-db -U challenge -d orders
    OLD: curl localhost:9001/verify
    NEW: curl challenge-01-missing-index:8080/verify
  Do this for all 7 challenges (01 & 07 = psql; 03-06 = edit file + rerun).

Hosting / TLS / Auth
=========================================================================
- One EC2 instance, t3.xlarge or t3.2xlarge, plain Docker + compose.
  NOTE: N teams x full challenge stack + code-server is heavy; size to team
  count and re-check the instance type.
- Security group locked to Cloudflare IP ranges plus your SSH.
- Caddy already on the box for automatic Let's Encrypt + subdomain routing.
- Cloudflare proxied in front for edge TLS.
- Cloudflare Access (Zero Trust) in front of CTFd (and ideally the team
  subdomains) for SSO / email-OTP; consider scoping each team subdomain to
  only that team's members.
- Tear down after the event.
